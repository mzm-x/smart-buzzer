# LANDING PAGE SYSTEM — PROJECT KNOWLEDGE & RULES

Generic blueprint untuk bangun landing page dengan log analytics, GTM dataLayer (GA4 standard), pixel tracking, UTM attribution, dan dashboard internal. Dokumen ini bisa langsung ditaruh di root project sebagai `CLAUDE.md` atau referensi tim.

---

## 1. CONFIDENCE-GATED EXECUTION RULE (CRITICAL)

**Selalu nyatakan confidence % sebelum eksekusi perubahan kode apapun.**

- Confidence ≥ 90% → eksekusi langsung tanpa approval.
- Confidence < 90% → STOP. Jangan eksekusi. Sajikan:
  1. Rencana eksak (apa yg berubah, di mana, urutannya)
  2. Confidence % per item + overall
  3. Penyebab < 90% (copy ambigu, layout uncertain, dependency unknown, dll)
  4. Pertanyaan klarifikasi atau opsi pilihan
  Lalu tunggu approval user sebelum tool call Edit/Write.

**Kalibrasi confidence jujur:**
- 95-100%: Trivial mechanical change (text swap, color change, hapus elemen).
- 90-94%: Scope jelas, single-file edit, copy & layout straightforward.
- 80-89%: Multiple sub-decisions (copy butuh interpretasi, mobile layout punya tradeoff).
- < 80%: Spec genuinely ambiguous, banyak interpretasi valid.

Jangan padding confidence biar skip approval. Jangan chain low-confidence changes biar rata-rata ≥ 90%.

## 2. SERVICE DELIVERY KNOWLEDGE (Source of Truth)

Semua copy di TNC, onboarding flow, landing page, support script, dashboard message **WAJIB konsisten** dengan source of truth ini. Update di satu tempat → update juga di file ini biar sinkron.

### Mobile section ordering rule (CRITICAL — applies to ALL LPs)
**Pada mobile (≤880px), gambar/visual SELALU di ATAS teks** di section image+text split apapun.
- Hero, case study, real reviews, dan section dua-kolom apapun harus reorder: image render duluan, text di bawah.
- Implementasi: CSS `order: 1` ke visual element, `order: 2` ke text element di dalam media query `@media (max-width: 880px)`.
- Alasan: user skim di mobile — visual proof dapat attention duluan, text reinforce.
- Desktop layout boleh tetap text-left + image-right.

## 3. UNIFIED GTM EVENT FLOW

### Core Principle
**Jangan bikin duplicate event.** Pakai SATU set standard GA4 + Meta event yang fire across ALL pages. Bedakan performance page via `page_location` di GA4 — bukan dengan bikin event terpisah per page.

### Complete Funnel: view_item → begin_checkout → add_payment_info → purchase

```
+-----------------------------------------------------------------------+
|                    UNIFIED GTM EVENT FUNNEL                           |
+-----------------------------------------------------------------------+
|                                                                       |
|  STEP 0: PAGE LOAD (All Pages)                                        |
|  +-- GTM: PageView (auto via GTM)                                     |
|  +-- FB Pixel: fbq('track', 'PageView')                              |
|  +-- TikTok: ttq.page()                                               |
|                                                                       |
|  STEP 1: PRICING SECTION VISIBLE (30% scroll or element visible)     |
|  +-- File: index.php                                                  |
|  +-- Trigger: Element visibility or 30% scroll depth                 |
|  +-- GTM dataLayer: view_item (per package, GA4 standard)            |
|  +-- Analytics: VIEW_ITEM → page_analytics.log                        |
|                                                                       |
|  STEP 2: ORDER NOW CLICK (Pricing Cards)                              |
|  +-- File: index.php                                                  |
|  +-- Trigger: Click any ORDER NOW button in pricing section           |
|  +-- FB Pixel: fbq('track', 'Lead')                                  |
|  +-- TikTok: ttq.track('SubmitForm')                                  |
|  +-- GTM dataLayer: generate_lead (for WhatsApp CTA clicks)          |
|  +-- Analytics: ORDER_[PACKAGE]_CLICK → page_analytics.log           |
|  +-- Action: Smooth scroll to #order-form, pre-select package        |
|                                                                       |
|  STEP 3: COMPLETE ORDER (Form Submit + Redirect)                     |
|  +-- File: index.php                                                  |
|  +-- Trigger: Click COMPLETE ORDER after filling form                 |
|  +-- FB Pixel: fbq('track', 'InitiateCheckout')                      |
|  +-- TikTok: ttq.track('InitiateCheckout')                           |
|  +-- GTM dataLayer: begin_checkout (GA4 + user_data captured here)  |
|  +-- GTM dataLayer: add_payment_info (fires on same click/redirect)  |
|  +-- Analytics: ORDER_SUBMIT → page_analytics.log                    |
|  +-- Customer: businessName + whatsapp + email → customer_data.log   |
|  +-- LocalStorage: save email + phone for purchase event bridge      |
|  +-- Action: Redirect to payment gateway URL                         |
|                                                                       |
|  STEP 4: THANK YOU PAGE (After Gateway Return)                       |
|  +-- File: thankyou.php                                               |
|  +-- Trigger: Page load (purchase confirmed)                          |
|  +-- FB Pixel: fbq('track', 'Purchase')                              |
|  +-- TikTok: ttq.track('CompletePayment')                            |
|  +-- GTM dataLayer: purchase (reads user_data from LocalStorage)     |
|  +-- Analytics: THANKYOU_PAGE_VIEW → page_analytics.log              |
|                                                                       |
|  STEP 4b: CLICK HERE TO CONTINUE (Thank You Page button)            |
|  +-- Trigger: Click CLICK HERE TO CONTINUE button                    |
|  +-- Analytics: PURCHASE_CLICK → page_analytics.log                  |
|  +-- Action: 400ms delay then redirect to payment gateway            |
|                                                                       |
+-----------------------------------------------------------------------+
```

**NOTE:** GTM is the single source of truth for all tracking. Direct `fbq()` and `ttq()` calls retained as fallback. GA4 standard ecommerce events. User data captured at `begin_checkout` on LP and persisted to LocalStorage for `purchase` event on thankyou.php.

### Unified Event Details

| Step | Trigger | GA4 dataLayer Event | FB Pixel Event | TikTok Event |
|------|---------|-------------------|---------------|-------------|
| Pricing visible | 30% scroll / element visible | `view_item` | - | - |
| ORDER NOW click | Pricing button click | `generate_lead` | `Lead` | `SubmitForm` |
| Add to Cart | Product page cart click | `add_to_cart` | - | - |
| COMPLETE ORDER | Form submit | `begin_checkout` | `InitiateCheckout` | `InitiateCheckout` |
| COMPLETE ORDER | Form submit (same click) | `add_payment_info` | - | - |
| Thank you page load | Page load | `purchase` | `Purchase` | `CompletePayment` |
| WhatsApp button | WA CTA click | `generate_lead` | - | - |

### 1. **index.php** — Landing Page (CUSTOMIZABLE)

**Boleh diubah:**
- Pricing amounts
- Checkout/gateway URLs
- Hero section content
- FAQ questions/answers
- Images dan branding
- Package names

**TIDAK boleh diubah:**
- Analytics tracking code di `<head>`
- GTM container code dan dataLayer pushes
- UTM tracking logic (`window.location.href`)
- Facebook Pixel code
- TikTok Pixel code
- `data-package` attributes di buttons
- GA4 event sequence (view_item → begin_checkout → add_payment_info → purchase)
- LocalStorage keys untuk user_data bridge

### 2. **analytics.php** — Backend API (NEVER MODIFY)

**Tugas:**
1. Receive POST dari index.php DAN thankyou.php (event_type, page_url, data, session_id)
2. Process: detect device, extract UTM, get IP+country, NO geo-blocking
3. Write ke `page_analytics.log` (13 columns TSV)

**Critical Features:**
- Input sanitization
- IP validation (prevent spoofing)
- Timeout 3 seconds
- UTM parsing dari `page_url` (6 params: source, medium, campaign, content, term, placement)

### 3. **log.php** — Dashboard (SHARED)

**Tugas:**
1. Read `customer_data.log` → Customer Tab (form submissions only, full UTM, follow-up toggle, CSV export)
2. Read `page_analytics.log` → Analytics Tab (page views, scroll depth, device breakdown, conversion funnel)
3. Process hierarchical data → Campaign Breakdown Tab (Campaign → Ad, side-by-side, top 5)

**customer_data.log Status Values:**
| Status | Meaning |
|--------|---------|
| `FORM_SUBMIT` | User submitted form with business data |
| `FOLLOWED_UP` | Admin marked as followed up |

**Conversion Rate** = Form Submits / Page Views (BUKAN pricing clicks / page views)

**Funnel** harus tampilkan 4 step: Page Views → Pricing Clicks (CTR%) → Form Submits → Conversion Rate

### 4. **thankyou.php** — Thank You Page

**Tugas:**
1. Receive URL params dari index.php: `pkg`, `dest` (gateway URL), `biz` (business name URL-encoded)
2. Display thank you card + "CLICK HERE TO CONTINUE" button (pulsing animation)
3. On page load: fire `purchase` dataLayer + `Purchase` FB pixel + `CompletePayment` TikTok
4. On button click: log `PURCHASE_CLICK`, 400ms delay, redirect ke gateway

**URL Format:** `thankyou.php?pkg=growth&dest=https://gateway.example.com/checkout/abc&biz=My%20Business`

**Boleh diubah:** thank you message, button text/styling, card design, footer.

**TIDAK boleh diubah:**
- Facebook Pixel code dan ID
- TikTok Pixel code dan ID
- Purchase event firing logic
- handlePurchaseClick function
- 400ms redirect delay (required pixels fire)
- analytics.php integration
- URL parameter parsing logic

**Security:**
- `pkg` sanitized dengan `htmlspecialchars()`
- `dest` validated dengan `filter_var(FILTER_VALIDATE_URL)`
- `biz` decoded lalu sanitized dengan `htmlspecialchars()`
- Invalid `dest` fallback ke landing page utama
- `handlePurchaseClick` punya one-time guard untuk prevent double-fire

## 9. UTM TRACKING SYSTEM

### UTM Parameters Captured (6 params — Standard Convention)

```
utm_source    -> Platform (e.g., meta)
utm_medium    -> Medium (e.g., paid_social)
utm_campaign  -> Campaign Name (e.g., Aul_US_LP_PROMO_V1)
utm_content   -> Ad Content (e.g., kv_localized-copy)
utm_term      -> Adset Name (e.g., LAA_ICO_L150D)
utm_placement -> Placement (e.g., Facebook_Mobile_Reels)
```

### UTM to FB Ads Mapping

| UTM Parameter | FB Ads Equivalent | Example |
|---------------|-------------------|---------|
| utm_source | Platform | meta |
| utm_medium | Medium Type | paid_social |
| utm_campaign | Campaign Name | Aul_US_LP_PROMO_V1 |
| utm_content | Ad Content | kv_localized-copy |
| utm_term | Adset Name | LAA_ICO_L150D |
| utm_placement | Placement | Facebook_Mobile_Reels |

### Standard FB Ads UTM Template

```
utm_source=meta&utm_medium=paid_social&utm_campaign={{campaign.name}}&utm_content={{ad.name}}&utm_term={{adset.name}}&utm_placement={{placement}}
```

### UTM Default Values (consistent across all files)

| Parameter | Default | Meaning |
|-----------|---------|---------|
| utm_source | `direct` | No UTM source detected |
| utm_medium | `none` | No medium detected |
| utm_campaign | `direct` | No campaign detected |
| utm_content | `-` | No ad content |
| utm_term | `-` | No adset name |
| utm_placement | `-` | No placement data |

### UTM Parsing (CORRECT vs WRONG)

```php
// CORRECT - parse_url + parse_str only (parse_str auto-decodes)
$parsed = parse_url($pageUrl);
if (isset($parsed['query'])) {
    parse_str($parsed['query'], $params);
    $utmSource = isset($params['utm_source']) ? trim($params['utm_source']) : 'direct';
}

// WRONG - triple decode corrupts encoded values
$decodedUrl = urldecode($pageUrl);              // decode #1
parse_str($parsed['query'], $params);           // decode #2 (auto)
$utmSource = urldecode($params['utm_source']);  // decode #3 - WRONG!
```

### CRITICAL — Always Use:

```javascript
// CORRECT
page_url: window.location.href  // Full URL with UTM params

// WRONG - UTM hilang!
page_url: window.location.pathname  // Just "/promo/"
```

## 10. CRITICAL IMPLEMENTATION RULES

### !! ABSOLUTE RULE — NO CLICK TRACKING IN customer_data.log !!

**customer_data.log records FORM SUBMISSIONS ONLY.**
- JANGAN write row ke `customer_data.log` saat user click pricing button
- JANGAN write row saat tidak ada business name + WhatsApp submitted
- Pricing button clicks tracked ONLY via: FB `Lead`, TikTok `SubmitForm`, GTM `generate_lead`, dan `ORDER_*_CLICK` ke `page_analytics.log`
- Kalau ada LP masih punya `log_pricing_click` fetch ke `log.php` — HAPUS

### DO NOT:

1. Pakai `window.location.pathname` untuk analytics (pakai `.href`)
2. Parse UTM dari `HTTP_REFERER` (pakai `page_url` dari frontend)
3. Tambah validation alert untuk WhatsApp number

## 15. NEW SEASONAL CAMPAIGN WORKFLOW

Saat bikin seasonal campaign baru (mid-year sale, back to school, black friday, dll), **selalu bikin folder baru dedicated** — JANGAN overwrite atau reuse `/seasonal/`.

### Folder Naming Convention

| Campaign | Folder |
|----------|--------|
| Mid-Year Sale | `/midyear/` |
| Back to School | `/backtoschool/` |
| Black Friday | `/blackfriday/` |
| Christmas | `/xmas/` |

### Required Files Per Campaign Folder

```
/new-campaign-folder/
+-- index.php          ← Landing page (new design + tracking)
+-- analytics.php      ← Copy exact dari LP existing
+-- log.php            ← Copy exact shared dashboard
+-- thankyou.php       ← Sesuai konvensi (atau gunakan root thankyou.php)
```

### Checklist Campaign Baru

```
[ ] Folder baru dengan nama benar
[ ] index.php — design baru, packages, prices, gateway URLs benar
[ ] analytics.php — exact copy
[ ] log.php — exact copy
[ ] GTM installed di index.php <head> + noscript
[ ] Meta Pixel: kalau GTM handle, JANGAN add direct fbq() init — kasih comment saja
[ ] TikTok Pixel installed directly (or via GTM)
[ ] pkgMeta defined dengan correct item IDs, prices
[ ] view_item dataLayer fires on pricing section visible
[ ] ORDER NOW: Lead pixel + SubmitForm TikTok + begin_checkout + add_payment_info + LocalStorage bridge + redirect
[ ] generate_lead dataLayer on WhatsApp CTA clicks
[ ] trackEvent uses application/json format
[ ] Packages baru added ke thankyou.php $packages
[ ] Mapping baru di thankyou.php $refMap
[ ] LP baru added ke /analytics/ source list
```

### Rotating Slot Workflow (jika ada folder rotating)

Kalau pakai rotating campaign slot (misal `/seasonal/`), **selalu backup file lama sebelum replace.**

1. Rename current `index.php` ke `index-{theme}.php` (misal `index-valentine.php`)
2. Place new campaign sebagai `index.php`

```
Before:  seasonal/index.php             (Valentine campaign)
After:   seasonal/index-valentine.php   (backup)
         seasonal/index.php             (new campaign)
```

JANGAN pakai nama generik kayak `index-old.php` atau `index-backup.php` — selalu pakai theme name.

## 16. PHRASES TO AVOID (Compliance / Clarity)

Sesuaikan dengan compliance industry kamu, tapi general rule:
- Hindari klaim "Zero X / 100% guarantee" yang risky secara compliance
- Replace dengan promise yang realistic: "automatic replacements", "full delivery commitment"
- Hindari outdated timeline yang bisa di-quote balik kalau target bisnis berubah
- Selalu sync wording di TNC, landing page, support script biar konsisten
